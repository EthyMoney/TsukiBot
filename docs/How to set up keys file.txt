This is where you put your api keys and other various keys and passwords that will be plugged into the bot during initialization. Put your own keys inside the empty quotes next to each field. Leave the dbl field alone unless you are posting stats to top.gg.

Every field above is read by the code. Keys for services the bot no longer uses have been removed from
this template: Graviex and STEX (support dropped), Alpha Vantage (stocks moved to Finnhub),
exchangeratesapi.io (superseded by openexchangerates.org), and the authenticated Coinbase pair
(only Coinbase's public endpoints are used). If your existing keys file still has them, they are
dead weight — and worth revoking at the provider rather than only deleting.


REQUIRED to start at all:

"token"      -> your bot's token from the discord dev portal
"tsukibot"   -> your postgresql database password
"dbAddress"  -> the hostname or IP of your postgresql server

The bot checks these three on startup and exits with a clear message naming any that
are missing, rather than failing later inside a command. If you start with -d (dev
mode) you also need "devToken".


For reference, here's what a few of the others actually are:

"etherscan"  -> your api key for etherscan (/eth and /gas)
"infura"     -> your infura project key (ENS lookups)
"finnhub"    -> your api key for finnhub (/stocks)
"coinalyze"  -> your api key for coinalyze (/ls). Without it, /ls says it is not configured.
"anthropic"  -> your Anthropic api key (/brief). Without it, /brief says it is not configured.
"coingecko"  -> your optional free CoinGecko Demo API key
"openexchangerates.org" -> your app id for openexchangerates (fiat rates used by /convert)

Commands whose key is missing report that they are not configured instead of
failing silently, so you only need keys for the features you actually want.


ABOUT THE COINGECKO KEY (worth doing):

A free CoinGecko Demo key moves the rate limit from per-IP to per-key, which cuts
the full market cache refresh from roughly 30 minutes down to a few. It also applies
to /cg contract-address lookups. For a Pro key, use "coingeckoPro" instead.

If no key is configured, contract lookups automatically fall back to CoinGecko's
public GeckoTerminal API with its lower public rate limit.


ENVIRONMENT VARIABLES

Every key above can also be supplied through the environment, which takes priority
over this file. That is what lets the Docker setup run without a keys file at all.
The names are:

  TSUKIBOT_TOKEN, TSUKIBOT_DEV_TOKEN, TSUKIBOT_DB_PASSWORD, TSUKIBOT_DB_ADDRESS,
  ETHERSCAN_API_KEY, INFURA_API_KEY, FINNHUB_API_KEY, CRYPTOCOMPARE_API_KEY,
  COINALYZE_API_KEY, OPENEXCHANGERATES_APP_ID, COINGECKO_API_KEY,
  COINGECKO_PRO_API_KEY, GOOGLE_CLOUD_PROJECT_ID, GOOGLE_CLOUD_KEY_PATH

The Anthropic key is read from ANTHROPIC_API_KEY, which is the standard name their
SDK already looks for.

Two more environment variables control Chromium, used for chart rendering:

  CHROME_PATH        -> path to your Chromium/Chrome executable, if it is not in
                        the usual place. Detected automatically otherwise.
  CHROME_NO_SANDBOX  -> set to "true" only if your host genuinely cannot run
                        Chromium's sandbox. It is on by default, and it is what
                        contains a compromised chart page, so leave it alone if
                        you can.


BOT ADMINS (optional)

  "botAdmins": ["123456789012345678", "234567890123456789"]

Who may run /usage, the usage telemetry reports. These reports span every server
the bot is in and name individual users, so they are owner-only by default.

You do not need to set this. On startup the bot asks Discord who owns the
application and grants access to that account (or to every member of the team,
for a team-owned app). This list is only for granting access to someone who is
not an owner.

Note that this is an array of user ID strings, unlike every other entry in this
file. Turn on Developer Mode in Discord to copy a user ID.


OWNER GUILD (required for /usage)

  "ownerGuild": "000000000000000000"

The server that owner-only commands are registered to. Right now that is just
/usage, the telemetry reports.

This exists because a globally registered command cannot really be hidden. Discord
treats default_member_permissions as a default that any server admin can override
in their integration settings, and it does not apply to DMs at all, so a global
/usage would be visible to every server admin and to anyone who DMs the bot.
Registering it to one guild means it does not exist anywhere else.

Set it before running "npm run deploy". If it is missing, deployment still succeeds
but warns that /usage was not registered anywhere.

Can also be supplied as the OWNER_GUILD_ID environment variable.


COINGECKO CREDIT BUDGET

A CoinGecko demo key allows 10,000 credits per MONTH, and one API request is one
credit. That works out to about 330 a day, which is less than it sounds: the
market cache used to page through all ~16,000 listed coins every 30 minutes,
costing roughly 96,000 credits a month, nearly ten times the allowance.

Two environment variables control the scheduled spend:

  CG_MAX_PAGES            -> pages of 250 coins to pre-cache. Default 4, so the
                             top 1,000 by market cap. Costs 48 x this per day.
                             Coins past the cap are not lost: they are fetched on
                             demand for one credit and cached briefly.

  ALERT_UNCACHED_INTERVAL_MS -> how often price alerts may fetch quotes for coins
                             the market cache does not carry. Default 1800000
                             (30 minutes).

                             Alerts on cached coins cost NOTHING: they ride the
                             cache refresh, so alert latency equals cache
                             freshness (30 minutes by default). This interval
                             only applies while an alert exists on a coin outside
                             the cached pages, and exists to stop one such alert
                             from fetching on every minute of the scan.

At the defaults the scheduled work costs 194 credits a day (5,898 a month), or up
to 242 a day (7,357 a month) while an alert is watching a coin outside the cache.
That leaves roughly 135 a day for user commands. Run /usage credits to see the
actual spend broken down by endpoint, with a projection against the quota.

Note that alert latency is bounded by the cache refresh, so shortening the cache
interval speeds alerts up too, at 4 credits per extra pass.

If you upgrade to a paid CoinGecko plan, raise CG_MAX_PAGES to cache more coins.


USAGE TELEMETRY OPTIONS (optional)

Everything about /usage beyond the raw reports is configured in one block. All of
it is optional; the defaults give you chart images, a dashboard on loopback, and a
Monday digest to the application owner without any configuration.

  "usage": {
    "defaults":  { "timezone": "America/Chicago", "days": 30, "limit": 15 },
    "images":    true,
    "creditBudget": 10000,
    "recipients": ["123456789012345678"],
    "dashboard": { "enabled": true, "host": "127.0.0.1", "port": 8090,
                   "publicUrl": "", "tokenTtlHours": 12 },
    "digest":    { "enabled": true, "dayOfWeek": 1, "hour": 9, "timezone": "America/Chicago" },
    "watchdog":  { "enabled": true, "intervalMinutes": 30 }
  }

"defaults"     -> what /usage uses when you leave days / limit / timezone blank,
                  so you stop typing your timezone on every report.
"images"       -> false to go back to text-only reports (the unicode sparklines).
                  Images are rendered with sharp, no Chromium involved.
"creditBudget" -> your CoinGecko plan's monthly credits. The credits report, the
                  digest and the watchdog measure against this. Default 10000 (a
                  demo key). Also CG_MONTHLY_CREDITS in the environment.
"recipients"   -> Discord user ids that receive the weekly digest and watchdog
                  DMs. When empty they go to the application owner(s) resolved
                  at startup. An array of id strings, like botAdmins.
"dashboard"    -> the browser dashboard. /usage dashboard prints a sign-in link
                  (a random token, valid tokenTtlHours, set as an HttpOnly
                  cookie). It listens on loopback, so open it on the machine the
                  bot runs on or through an SSH tunnel (ssh -L 8090:127.0.0.1:8090
                  host). "publicUrl" is only what the link says, for when a
                  tunnel or reverse proxy changes the address. Environment:
                  TSUKIBOT_DASHBOARD_ENABLED / _HOST / _PORT / _URL.
                  In Docker set host to 0.0.0.0 and publish "127.0.0.1:8090:8090";
                  see docker-compose.yml.
"digest"       -> the weekly DM. dayOfWeek 0 = Sunday .. 6 = Saturday, hour 0-23,
                  fired in "timezone" (not the server's). TSUKIBOT_DIGEST_ENABLED.
"watchdog"     -> the periodic checks (error-rate spike, latency regression,
                  CoinGecko 429s, credit projection over budget, dropped telemetry
                  batches). Each condition DMs at most once a day.
                  TSUKIBOT_WATCHDOG_ENABLED.

Neither the digest nor the watchdog runs in dev mode (-d), so a development
instance never DMs anyone.
